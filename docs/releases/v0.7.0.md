# Caterva v0.7.0

**Every number on a public surface is measured, derived from the tree, or
removed (ADR 0180), and the engine works again on macOS 27.** This is the
V7 release. The commands are the ones 0.6.0 registered, unchanged; what
changed is that the README, the site, the landing page and the guides now
print only counts, versions and claims a guard can check, and that scipy
1.15.3, which no longer imports on macOS 27, is replaced on Python 3.11 and
later. The notes for 0.6.0 still describe the claims, `caterva why`,
`caterva verify` and the Studio screens.

## The engine on macOS 27

- **scipy is 1.16.0 on Python 3.11 to 3.13.** On macOS 27.0.1, scipy
  1.15.3's cp313 arm64 wheel fails in the dynamic loader on
  `import scipy.sparse.linalg`, and `scipy.optimize` with it, so steady-state
  analysis and influence ranking stopped working in a Python 3.13 install
  of 0.6.0 there. 1.15.2 fails the same way; 1.16.0, the next release,
  imports, as do 1.17 and 1.18.0 (checked 2026-10-31). Python 3.10 keeps
  1.15.3, the last line with cp310 wheels; whether its cp310 wheel shows the
  same failure on macOS 27 is unchecked.
- **The Mac app and the app folders carry the new pin**, because they are
  frozen on Python 3.12. Whether the cp312 wheel the 0.6.0 app carries
  failed the same way was not checked. On 2026-11-01 the 0.7.0 wheel,
  installed alone into a fresh Python 3.13 on macOS 27, found a steady
  state and ranked influence.
- certifi is 2026.10.19.

## Every public number measured, derived or removed

- **The landing page reads its facts from the tree.** Its guard count,
  suite sizes, data sources and the release it offers come from a generated
  `repoFacts.json`; `scripts/check_landing_test_counts.py` fails when that
  file, a row's collected count or its pass count is stale. The download
  box offered v0.4.0 after v0.6.0 was out, and the 404 page named a v0.7.0
  that did not exist; both now read the release tag from
  `caterva/__init__.py`.
- **The counts in the README and contributor docs are checked against the
  tree.** `scripts/check_documented_counts.py` collects the suites and fails
  when a count in prose disagrees with them. It now reads "79 guards" as
  well as "79 guard scripts"; the narrower pattern had let three stale
  guard counts and a domain count stand in `docs/readmes/`.
- **Live checks end in one of three states.** `scripts/verify_citations_live.py`
  and `scripts/verify_values_live.py` report every check as matched,
  mismatched or unreachable (exit 0, 2, 1). DOIs are checked through the
  CrossRef API, PMIDs by title against their topic, and DOIs again in CORE
  as a second index. BRENDA reference 740253 is no longer checked as a
  PubMed id: as a PMID it is an unrelated 1978 paper.
- **One licence, checked everywhere it is declared.**
  `scripts/check_license_consistency.py` reads every manifest, the OpenAPI
  spec and `pyproject.toml`, and fails when a file it is told to read is
  missing. The root `openapi.yaml` declared another licence; it now says
  Apache-2.0.
- **The record is corrected where it was wrong.** 0.5.0 and 0.5.1 were
  released only as candidates; the 18 Terrium-sim repositories are private,
  17 of them copies pushed on 2026-08-12 under the old name (the 18th,
  demo-repository, is GitHub's demo), and none has been pushed since;
  development is at github.com/math12345678/caterva.

## Removed

- **The archived resolvers left the live code.** `Tests/epidemiology_resolver.py`,
  `Tests/popgen_resolver.py`, their tests and `requirements-popgen.txt`
  moved to `archive/legacy_domains/`. v0.6.0 is the last release that ships
  them; v0.4.0 is the last that runs the domains they served. A test fails
  when a guard or set-up check names a path that moved, still probes for
  stdpopsim, or live code imports one of them.
- **The API server's epidemiology bridge and the `wright_fisher` field**,
  which no live domain reached. Its query parser accepts only the live
  parameter names and refuses a list where a number belongs.
- Root probe scripts, a screenshot and a committed job log.

## Also in this release

- `caterva-site`'s shell offers the five live domains, runs
  Michaelis-Menten with the showcase's hexokinase constants (Km and kcat)
  and Gillespie with the domain catalogue's example rates, in the browser,
  and answers an archived domain with its archive date.
- The dashboard shows the literature score on a 0-1 scale, labelled a
  heuristic and not a probability, and the TypeScript CLI prints
  `Literature agreement: 0.xx (heuristic)` (or "not applicable") where it
  printed `Confidence: X%`.
- Monitoring files moved to `deploy/monitoring/`, their ports bound to
  127.0.0.1, and Grafana's admin password has no default.
- Two tests that depended on the runner: a Ki fixture is read as UTF-8, and
  an MD smoke test accepts areas equal as printed on either side of a
  judged boundary.

Nothing about the science changed in the commands that existed in 0.6.0.

## Upgrading a Docker deployment

`docker-compose.yml` no longer bind-mounts `./caterva-jobs.jsonl`, which
broke on a fresh clone because Docker created a directory in the file's
place. The job store is now `./data/caterva-jobs.jsonl`
(`CATERVA_JOBS_FILE=/app/data/caterva-jobs.jsonl`). To keep a deployment's
job history, move `caterva-jobs.jsonl` into `./data` before `up`. On Linux,
create the directories first, because the container runs as uid 1001:

```
mkdir -p data logs && sudo chown 1001:1001 data logs
```

## What is not in this release

- What 0.6.0 listed as not in it is still not in it: a row's
  interpretation is not yet a claim of its own, NCBI, UniProt and PubChem
  answers are not pinned, and a bundle carries no signature.
- The Mac app is still not signed with an Apple Developer ID or
  notarised. The 0.6.0 notes, "The Mac app", say how to open a downloaded
  copy; an installed 0.5.1 release candidate or 0.6.0 offers this version
  through Check for Updates once the plain `v0.7.0` release is out.

## How this release was cut

As for 0.6.0: the first attempt is a release candidate, `v0.7.0-rc.1`,
which runs the whole pipeline and publishes a pre-release; the plain
`v0.7.0` tag is cut after a candidate has shipped every artifact. The
release stops, and publishes nothing, if the update key (a repository
secret) is missing.

## Install

From the [releases page](https://github.com/math12345678/caterva/releases),
each file listed with its SHA-256 in `SHA256SUMS`:

- `Caterva-0.7.0-macos-arm64.dmg`, the Mac app (Apple silicon, macOS 14 or
  later);
- the app folders, `caterva-0.7.0-linux-x86_64.tar.gz`,
  `caterva-0.7.0-macos-arm64.tar.gz` and `caterva-0.7.0-windows-x86_64.zip`;
- the Python wheel, `caterva-0.7.0-py3-none-any.whl`, and the source
  distribution, `caterva-0.7.0.tar.gz`;
- `Caterva-0.7.0-macos-arm64.zip` and `appcast.xml`, what the app's updater
  downloads and reads, and the corresponding source of the libSBML the
  folders carry, of the python-libsbml binding and of the two libraries
  that embed it, with `libsbml-copies.tsv`, which lists each copy.

Or clone the repository and run `make setup`.
