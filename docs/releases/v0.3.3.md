# Caterva v0.3.3

**A model whose constants are sourced.** Scientific simulation for teaching labs and
research groups, built so that every number in a model can be traced to
where it came from, and so that a number nobody measured is labelled as
one, never invented.

v0.3.0 made it downloadable, v0.3.1 made it learnable. This one makes the
central claim true of the experience and not just the code: `compose`
searches the literature, and every number in the model it returns says
where it came from.

```bash
caterva compose "Michaelis-Menten with a competitive inhibitor" \
    --subject 1.1.1.27 --organism "Homo sapiens" --substrate pyruvate
```

```
**2 of 3 constant(s) came from the literature**, searched for `1.1.1.27`
in Homo sapiens, substrate pyruvate.

| `reaction_Ki`   | 0.00059 mM | literature (Homo sapiens) | BRENDA ref 739793 |
| `reaction_Km`   | 0.03 mM    | literature (Homo sapiens) | BRENDA ref 286469 |
| `reaction_kcat` | 100.0 1/s  | **placeholder** | no value in the organism
  requested; measurements exist in other organisms ... -- available in:
  Escherichia coli, Gallus gallus, Oryctolagus cuniculus, ... |
```

Below the table, the report says three more things a cited number alone
would hide:

- **What the evidence did not settle.** Two papers rank 0.03 and 0.398 mM
  equal for that Km — a 13.3-fold spread — and the report names both
  references rather than presenting the pick as the answer. One paper
  reporting two rows is described as exactly that, not as a controversy.
- **The conditions each value was measured under**, and whether two
  constants can share a model at all (1 pH unit, 10 °C are the thresholds).
  A source that stated no conditions is named as such.
- **Why a constant is missing**, in the resolver's words. "Not found" is
  four different facts: the value exists in another organism, exists only
  in distant ones, exists in papers nobody extracted, or does not exist.
  Only the last means stop looking.

A search that cannot run — an enzyme name that means six enzymes, a Km with
no `--substrate` — exits **3** and says why, per the CLI's own contract. It
needs the source checkout, not the app folder, and `make setup` now
installs the `caterva` command there.

`make cite EC=1.1.1.27 SUBSTRATE=pyruvate ORGANISM="Homo sapiens"` gives the
same measured constants as a standalone document. See
[the guide](../USING_CATERVA.md) and ADR 0178, which records nine defects
found and fixed on the way, including a citation formatter that had been
reducing every BRENDA reference to the same enzyme-page URL.

## Download and run (no Python needed)

Pick the folder for your machine from the assets below, unpack it, and run
the one executable inside:

| file | for |
|---|---|
| `caterva-0.3.3-macos-arm64.tar.gz` | Apple silicon Macs |
| `caterva-0.3.3-linux-x86_64.tar.gz` | Linux, x86_64 |
| `caterva-0.3.3-windows-x86_64.zip` | Windows, x86_64 |

```bash
tar xzf caterva-0.3.3-macos-arm64.tar.gz
cd caterva
xattr -dr com.apple.quarantine .        # macOS only, once: see below
./caterva compose "a toggle switch between two repressors"
./caterva sim wf --help
./caterva --version
```

On Windows: unzip, open a terminal in the folder, and run
`.\caterva.exe compose "..."` (PowerShell needs the `.\` prefix).

**macOS quarantines the whole folder** after download, because it is not
signed with an Apple Developer ID, and refuses the first run ("cannot be
opened because the developer cannot be verified"). "Open Anyway" in System
Settings approves one file and does not unblock the libraries under
`_internal/`, so it will not get you running. The `xattr` line above, run
once from inside the folder, does. On Windows, SmartScreen's "Windows
protected your PC" prompt has a "More info > Run anyway" path. `README.txt`
inside each folder says the same for its platform.

Intel Macs: there is no folder for you in this release; install the wheel.

**Then read [the guide](../USING_CATERVA.md)**, or just run `./caterva` with
no arguments: both start with the one rule that explains most refusals (it
recognises a *shape*, never a *subject*) and three commands worth typing in
order. Every folder carries a condensed version in its own `README.txt`.

## Or install the wheel

```bash
pip install caterva-0.3.3-py3-none-any.whl
caterva compose "a toggle switch between two repressors"
caterva --version                     # the same command the app folder runs
```

Python 3.10 to 3.13. Dependencies are pinned and fetched by pip; nothing is
bundled in the wheel.

## What the release page proves

Every asset on this page was produced by `.github/workflows/release.yml`
from the tagged commit, and the workflow publishes nothing unless all of
the following held:

- the wheel and sdist were built twice, in independent jobs, and their
  `SHA256SUMS` were byte-identical (both artifacts are reproducible from
  the tag: `git checkout v0.3.3 && python3 scripts/build_release.py`);
- the wheel installed into a fresh interpreter on Linux, macOS and Windows
  at Python 3.10 and 3.13, and `caterva-compose` built, simulated and
  graded a model to a `VERDICT:` line from an empty directory, with
  `caterva` imported from `site-packages` and nothing of the repository on
  the path;
- each app folder, frozen from that installed wheel, ran `--version`,
  `sim --help`, a simulated time course, an SBML export and an
  expansion-library shape from an empty directory, contained
  python-libsbml's extension as one separate replaceable file, recorded
  the other libSBML copies it carries, and carried the licence files of
  everything it conveys;
- the corresponding source for every libSBML version reported, and for
  libroadrunner and Antimony, was fetched from upstream; a failed fetch
  publishes nothing.

`SHA256SUMS` on this page covers every asset. The app folders are not
byte-reproducible (PyInstaller's bootloader and archive carry timestamps);
the wheel and sdist are.

## What is inside the app folder, and the LGPL

The folder holds the Python runtime, Caterva, and the libraries Caterva
uses. libSBML (LGPL-2.1) is in it three times: python-libsbml's extension,
a separate file under `_internal/libsbml/` you may replace with your own
interface-compatible build (`README.txt` names the path), and two copies
compiled into libroadrunner and Antimony by their upstream projects, which
are not separately replaceable. For that reason the corresponding source
of every libSBML version the folders carry, and of libroadrunner and
Antimony themselves, is attached to this page beside the folders
(`libsbml-<version>-source.tar.gz`, `roadrunner-2.8.0-source.tar.gz`,
`antimony-2.14.0-source.tar.gz`, the python-libsbml sdist) and covered by
the same `SHA256SUMS`; `libsbml-copies.tsv` lists which file carries which
version on which platform. libSBML's terms and the LGPL text are in
`licenses/python-libsbml/`; every other component's licence is in
`licenses/` too, listed in `licenses/README.txt`. NOTICE states the
position for each artifact and names the two questions it leaves to
counsel.

## What it does

The composer recognises eleven mechanisms deterministically, with no
language model and no API key, and builds a reaction network from a
library of motifs whose every constant is labelled a placeholder until a
measurement replaces it. On the result it runs, and reports on: steady
states and their stability; whether every number going in and coming out
is physically possible; conservation laws, dimensional balance and
cross-checks; which unmeasured constant the conclusion rests on and how
robust it is to resampling; and knockouts that remove the gene. Every
check distinguishes *could not run* from *ran and passed*, on the page.

## What is not in this release

- **PyPI.** A separate decision; the name has not been checked.
- **Code signing.** No Apple Developer ID or Windows certificate. The
  first-run prompts above are the consequence.
- **An Intel-Mac folder.**
- **Literature search from the wheel or the app folder.** The BRENDA
  resolvers live in `Tests/` and ship in neither. From those, `--subject`
  still builds and checks the model, says "No literature search is possible
  from this installation; clone the repository to run one", and exits 3.
  From a clone with `make setup`, it searches.
- **The api-server and landing site.** TypeScript, deployed separately.
- **A public repository.** This Release is visible to collaborators. What
  going public still needs is listed in `docs/status/2026-09-21.md`.

## Why 0.3.3

A minor-sized change released as a patch number, because 0.3.2 was never
published as a final release (only its candidate was tagged) and version
numbers are not skipped. What it adds: `compose` gains the literature search, the report gains the
disagreement, conditions and absence reasons, and the CLI gains `caterva`
everywhere and an honest exit code. Nothing about the science of the
mechanism library changed. The public API is not frozen and the library is
35 shapes. See `CHANGELOG.md` and ADR 0178.
