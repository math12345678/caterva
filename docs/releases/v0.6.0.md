# Caterva v0.6.0

**A model's numbers carry their evidence, and a second program can re-check
them.** `caterva compose ... --claims DIR` pins every BRENDA page the search
read, records each constant as a claim whose identity is its derivation, and
writes a bundle you can hand to someone else. `caterva why` prints a claim's
derivation down to the bytes it came from, and `caterva verify` re-checks a
bundle offline with code that imports nothing of what wrote it. The search
itself is as in 0.5.1: it reads BRENDA live, and nothing in Caterva serves a
recorded page as the current one. The notes for 0.5.0 and 0.5.1 still
describe Caterva Studio, the Mac app and the commands.

## Claims: `--claims DIR`

```
caterva compose "Michaelis Menten" --subject 2.7.1.1 --organism human --substrate glucose --claims ./claims
```

- **What it writes.** A directory: every BRENDA page the resolver read, as
  the bytes it read them (gzipped, named by their sha256), the rows it took
  from them, and one claim per constant: cited (a row, with byte spans in
  the page for the reference id, the value and the commentary), chosen (a
  starting amount you set), placeholder (the table that would have supplied
  it, and did not), refused (no row on the pinned page matched what the
  resolver reported; the candidates are named, and no citation is given),
  and one computed claim for the model, over all of them. The report ends
  with a `## Claims` section naming the root claim, the counts per kind and
  the line `Re-check offline: caterva verify DIR`.
- **A claim's id is its derivation.** The rule that produced it, with its
  version and the decision record behind it; what it consumed; the spans it
  certifies; and, for a cited or chosen value, the value itself. A
  recomputed value is not in its id: a tolerance is, so a re-integration
  within the tolerance is the same claim. Changing any of that changes the
  id, and a stored id that does not match its contents is caught.
- **Snapshots are dated records, never a cache.** Each carries the day it
  was retrieved, beside its id. No later search reads one. Without
  `--claims` nothing changes.
- **Exports carry the ids** when you pass both flags: `--export csv` gains
  a final `claim_id` column, the SBML's parameter notes gain a `CLAIM` line,
  the Antimony a `# claim:` comment. Without `--claims` the exports are
  byte for byte 0.5.1's.

## Why a number: `caterva why`

```
caterva why claim:sha256:<hex> --bundle ./claims
```

prints the claim, each rule with its decision record, each certified span
and the text at it, the row's fields, the snapshot's URL, date, hash and
licence, and, when the bundle holds BRENDA's literature page for the row's
reference, the paper's title and PubMed id read from that page. A ref that
is not in the bundle is refused (exit 3).

## Re-check offline: `caterva verify`

```
caterva verify ./claims
caterva verify ./claims --json
```

- **What it checks.** Every pinned page hashes to its id. Every row and
  claim id recomputes from its stored fields. Every cited claim's row is in
  the bundle, its page is in the bundle, and the reference id and the value
  occur within one table row of that page. Every certified span lies inside
  its page and reads as its text. The chosen row is not dominated by an
  alternative, when the ordinals were carried. A stated unit factor
  multiplies out, within the claim's tolerance. Every computed claim's
  inputs exist, and the root claim is computed. One line per check, then a
  summary; exit 0 when all passed, 3 when one failed (the first failing
  claim is named on stderr), 2 for a bundle it cannot read.
- **What it says it did not check.** Regenerating the Antimony and replaying
  the integration are listed as not checked, with the reason. A check that
  could not run is never reported as passed.
- **What it cannot tell you.** Whether the biology is right. It checks
  derivations and stated reasons against pinned bytes. The word is
  re-checkable.
- **It shares no code with the composer.** `caterva/check/` imports only
  the standard library, and a guard reads its imports on every build.

## Also in this release

- **A refusal for a missing substrate names the substrates.** When
  `--subject` resolves and the model needs a Km but no `--substrate` was
  given, the refusal now lists the substrates BRENDA holds Km rows for in
  your organism, with the number of rows for each, so the re-run is a
  choice you can make. It still never picks one for you.
- **A language model may propose an EC number, never supply one.** In the
  API server's resolver the model is asked for the enzyme name as stated in
  the query, and for an EC number only if the query text itself contains
  one; a number it returns that is not in the query is dropped and the
  response says so. When the query names no organism the model no longer
  fills one in: the runner's own default applies and is reported as a
  chosen assumption, as `caterva compose` reports it. When both a name and
  a number arrive, the number is used only if the name resolves to it, or
  to a set of enzymes it is one of; otherwise the run is refused as
  `ec_mismatch`, naming both. A name the finder has no answer for leaves
  the number standing, and the log says it was not checked.
- **A labelled set.** `Tests/fixtures/labelled/` holds the 25 human
  D-glucose Km rows of the recorded hexokinase page, each labelled by hand
  with the isozyme it belongs to and how that was read (the row's words,
  the paper's title, the UniProt accession). It is for scoring a future
  isozyme rule, and its README says what was checked on which date.
- **A placeholder-DOI guard.** No tracked Markdown may print a DOI under an
  example prefix; `docs/ARCHITECTURE_RIGOR.md`, which did, is deleted and
  replaced by `docs/ARCHITECTURE.md`, one present-tense page naming the
  decision record behind each layer.

Nothing about the science changed in the commands that existed in 0.5.1.

## What is not in this release

- **Readings and labels.** A row's interpretation (which isozyme, which
  variant, which condition) is not yet a claim of its own, and the
  resolver's ranking is recorded as its pick, not re-derived; the report's
  "where the evidence did not settle" section is still where the spread is
  shown. That is milestone M3 of the plan. Defeats as data, the persistent
  engine, audits, the ledger and synthesis are M4 and after.
- **The Studio shows no derivation view.** The claim, its row, its snapshot
  and its reference are in the bundle and in `caterva why`; a screen for
  them, with a re-check action, is not in this release.
- NCBI, UniProt and PubChem answers the search reads are not pinned; only
  BRENDA's enzyme and literature pages are.

## How this release was cut

As for 0.5.1: the first attempt is a release candidate, `v0.6.0-rc.1`,
which runs the whole pipeline and publishes a pre-release; the plain
`v0.6.0` tag is cut after a candidate has shipped every artifact.

## Install

The Mac app (`Caterva-0.6.0-macos-arm64.dmg`), the app folder (a `.tar.gz`
or `.zip` per platform), the Python wheel, or a clone and `make setup`,
from the [releases page](https://github.com/math12345678/caterva/releases).
Every file is listed with its SHA-256 in `SHA256SUMS`. A 0.5.1 app offers
this version in the app (Caterva menu, Check for Updates).
