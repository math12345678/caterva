# --- Why `--only` exists: the numbers ---
#
# Measured 2026-08-15, recorded so nobody re-derives it.
#
# One mutate.py iteration is two pytest runs, and the harness overhead is
# negligible: 39.8 s against 20.2 s for the bare suite. A set of N mutations
# therefore costs N+1 runs. ADR 0062 is 8 mutations = 9 runs = ~180 s,
# against a 178 s ceiling on a single command in the environment these were
# written in. 0078's suite is slower again, because it shells out to
# check_documented_counts.py and collects the whole test suite.
#
# Caching does not close that gap. Repeated timings of *identical* code
# ranged 20.9-30.4 s, because several agents run suites on this machine at
# once, and that spread alone exceeds the margin being chased.
#
# `--only` splits the RUN without splitting the RECORD, which is the
# distinction that matters: the set file stays one piece of evidence.
# 0062 was completed in two invocations of four rows, 0078 in one of three
# and one of two. **Both are now verified and neither is parked.** This note
# is kept because the cost is a property of the environment, not of those
# two sets, and the next slow suite will hit it too.

# --- Outstanding verification, not a table ---
#
# ADR 0083: the harness reported one mutation as NOT CAUGHT and then, minutes
# later, as CAUGHT -- same set file, same tree. A false NOT CAUGHT reads as a
# real gap in the tests, which is the failure class ADR 0069 exists to remove,
# reappearing inside the tool written to remove it.
#
# PARTIALLY VERIFIED. The question splits in two:
#
#   Half one -- the harness's own logic (write -> run -> read verdict ->
#   restore): DETERMINISTIC. Five consecutive runs of one mutation against a
#   pytest suite, five `caught`.
#
#   Half two -- a JavaScript runner's transform cache, which is the mechanism
#   the mtime fix addresses: NOT TESTED, and not testable here. One jest
#   invocation of the eight-test file this appeared in costs 70.7 seconds
#   (measured). Baseline + mutation is 141 s against a 178 s per-call ceiling,
#   leaving no room to repeat; repeating across calls destroys the rapid
#   succession that produced the disagreement.
#
# So the fix is reasoned and harmless, and unproven for the case it was
# written for. On a machine without the ceiling:
#
#   for i in 1 2 3; do python3 scripts/mutate.py \
#     --set docs/mutations/adr-0056-column-claimed-a-source.json --only J3; done
#
# Three identical verdicts is the result being looked for. Any disagreement
# means the mtime fix is not the whole story.
#
# UPDATE 2026-08-18 -- THE MTIME FIX IS NOT THE WHOLE STORY.
#
# Half two above was "NOT TESTED, and not testable here". It has now been
# observed, in a suite small enough to fit the ceiling.
#
# ADR 0119's Y4 mutates `plausible()` in suggestResolveCommand.ts to return
# true unconditionally. Direct execution of the mutated module:
#
#     under mutation -> {"enzyme":"model","substrate":"model","organism":"model"}
#
# and `suggestResolveCommand.test.ts` asserts `toBeNull()` on that exact
# query. The test MUST fail. Jest reported 15 of 15 passing, so the runner
# did not see the change -- with `--no-cache` passed TWICE (injected by
# mutate.py per ADR 0083, and again in the --test override).
#
# So `--no-cache` does not close it. What does is unknown; candidates are
# ts-jest's own transform cache keyed independently of jest's, and the
# haste map. Somebody should find out before another NOT CAUGHT in a
# TypeScript suite is believed.
#
# THE ASYMMETRY STILL HOLDS, and it is why no past verdict is retracted: a
# stale cache can only manufacture a false NOT CAUGHT, never a false
# "caught". Every `caught` in this repository stands. What is now in doubt
# is every NOT CAUGHT recorded against a jest suite.
#
# NOTE ON THE `.unverified` SUFFIX ABOVE: adopted from a concurrent agent who
# hit this same ceiling independently and parked two set files rather than
# ship them. It is the better convention and it is now this file's, because a
# set nobody has run to completion is exactly the unchecked evidence the
# mechanism exists to replace. The `--only` flag added for ADR 0083 splits a
# run without splitting the record, and may let those two be finished in
