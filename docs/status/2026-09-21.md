# Repository status, 2026-09-21

**v0.3.0 is the first release the repository publishes itself, and the
first downloadable as an app.** Pushing the tag runs
`.github/workflows/release.yml`, which builds, rebuilds, installs, runs and
freezes before it creates the GitHub Release with every artifact attached.
This supersedes [2026-09-19](2026-09-19.md), whose open problem 1 ("the
GitHub Release is not created") is what this pass closes. Everything here
was measured on the commit it is part of unless it says otherwise.

Unaffiliated with Tellurium. See [NOTICE](../../NOTICE).

## 1. What "released" now means

| step | who does it | what it proves |
|---|---|---|
| `git push origin v0.3.0-rc.N` until green, then `v0.3.0` on that commit | a person | the version is named; a candidate's failure costs a number, not a final tag (it took four) |
| `artifacts` job | CI | wheel + sdist by `scripts/build_release.py`; the wheel has no tests, no conftest, LICENSE and NOTICE inside, every module under `caterva/` |
| `reproduce` job | CI | a second independent build gives byte-identical `SHA256SUMS`, or nothing is published |
| `verify` job, 6 legs | CI | the wheel installs into a fresh interpreter on Linux, macOS, Windows at Python 3.10 and 3.13; from an empty directory it integrates a time course (`Integrated to t=`, no `no time course`), exports SBML, and builds an expansion-library shape; `caterva` came from `site-packages` |
| `app` job, 3 legs | CI | `scripts/build_app.py` freezes the installed wheel into one folder per platform, refuses it unless python-libsbml's copy of libSBML is a separate replaceable file and every conveyed licence is inside, records the libSBML copies compiled into libroadrunner and Antimony, and runs the frozen binary from an empty directory |
| `publish` job, sources step | CI | fetches the corresponding source of every libSBML version the folders report, and of libroadrunner and Antimony, from upstream; a failed fetch publishes nothing |
| `publish` job | CI, with the run's own token | `gh release create` with `docs/releases/v0.3.0.md`, all artifacts, one `SHA256SUMS` |

No person's credential is on the path. The `gh` token on the authoring
machine is still invalid; it is no longer needed for a release.

## 3. What changed in this pass

1. **`.github/workflows/release.yml`** (ADR 0177). Tag push or manual
   dispatch for an existing tag, with `publish: false` to build and verify
   without publishing.
2. **`scripts/build_app.py`**, **`caterva/app.py`**, **`requirements-release.txt`**,
   **`third_party_licenses/LGPL-2.1.txt`**: the app folder and what it must
   carry. **`caterva/core/data/`**: packaged copies of `docs/data-sources.json`
   and the identifiers.org capture, which the engine reads at import; the
   0.2.0 wheel had neither, so `caterva-compose --export sbml` crashed from
   every installed copy. Found by reading, fixed, proved from an installed
   wheel in an empty directory, and pinned by `test_packaged_data.py`.
3. **`scripts/build_release.py`**: the sdist is normalised (sorted members,
   epoch mtimes, uid/gid 0, gzip mtime 0) and re-read and compared before
   it is kept. Both artifacts are reproducible now, not one.
4. **NOTICE**: the licence position artifact by artifact. `docs/LICENSING.md`
   and `scripts/check_dependency_licenses.py` amended to match. The
   PyInstaller licence (GPL-2.0-or-later WITH Bootloader-exception) is
   recorded, and `requirements-release.txt` is in the manifests both
   guards read.
5. **`CHANGELOG.md`**: a duplicated, truncated block that the 0.2.0 commit
   introduced (an edit anchored on the wrong `## Unreleased`) is removed;
   the 0.3.0 entry added. `SECURITY.md` names supported versions. The
   landing page's changelog lists the three tagged versions instead of
   saying no release process exists.
6. **`docs/releases/v0.3.0.md`**, this document, `docs/README.md` rows.

## 3b. 2026-09-22: it explains itself (v0.3.1)

The release worked and taught nothing. `docs/USING_CATERVA.md` is the
guide: the shape-versus-subject rule that explains most refusals, the first
three minutes, how to read each report section, and a recipe per real
question (`--screen` which step matters, `--design` what to measure next,
`--robustness` does the conclusion survive the placeholders, `--scale` /
`--predictions` is it physically possible in and out). Every command in it
was run before it was written down, and
`caterva/tests/test_using_caterva_guide.py` fails if any flag, shape, export
format, subcommand or the stated mechanism count drifts from the code --
verified by mutating the guide four ways and watching each fail.

`caterva` with no arguments is now that quick start rather than a six-line
usage, with the mechanism count read from the grammar; the app folder's
`README.txt` carries a condensed version for someone who has no repository.
