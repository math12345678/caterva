Three outcomes, three exit codes

0

Exit code 0. Produced

Every constant with its citation, and every disagreement named.

3

Exit code 3. Refused, and said why

An enzyme name that means more than one enzyme, or a constant nothing measured. A refusal is an answer: no value was invented to fill the gap.

2

Exit code 2. The question was not well formed

Nothing was looked up. Not the same as "nothing was found".

Most tools collapse these. They are different facts, and a tool that reports "no result" when it never looked teaches you to read an absence of evidence as evidence of absence.

    Pipeline / text description

      The architecture on this page is an illustration of how a run is assembled; the values Caterva reports, here and in the tool, are real and cited. Caterva is pre-release and does not guarantee correctness.

      01 / Evidence

      Science should leave a trail.

      Caterva does not silently choose a number. Every value is linked to a source, bounded by the conditions that source declared, or marked for review.

      Evidence rail / parameter Km Select a link to inspect

      Evidence microscope / Deep inspection

      Inspect the reason,
      not just the result.

      A scientific parameter is not a number until its scope, basis, and review state are visible.

      A real value, shown with everything that qualifies it. Where the record is silent, the page says so.

      02 / Trust layer

      Code that runs is not
      necessarily science that holds.

      Generation, execution, tracing, correctness, critique and presentation are separated, because each one fails in a different way.

      Generation is one step.
      Verification surrounds it.

      03 / Execution

      Run where the method permits.
      Prepare where it does not.

      Work is routed by real computational limits, not by a single blanket claim.

      System manifest / V1.0

      System manifest, version 1.0

      1. 01

        Caterva does not silently choose a measured parameter.

      2. 02

        Caterva does not treat code execution as scientific validation.

      3. 03

        Caterva does not hide the assumptions that shape a run.

      4. 04

        Caterva does not promise browser execution where real compute is required.

      5. 05

        Caterva preserves the path from question to result.

      Science should not depend on invisible assumptions.
